## 💡 Tips for Tricky Output Questions in Live Interviews

When asked to predict output in an interview:

1. **Don't Guess** — Think through the logic step-by-step
2. **Ask Clarifying Questions** — "Will StrictMode be enabled?", "Is this React 18+"
3. **Explain Your Reasoning** — Explain the mechanism, not just the output
4. **Test Your Knowledge** — Ask "Why does X cause Y behavior?"
5. **Mention Edge Cases** — Show you understand the broader context
6. **Reference React Docs** — "According to React docs, batching happens because..."
7. **Talk About Performance** — Discuss implications of the behavior
8. **Relate to Real Code** — Connect to patterns you've seen in production

### Example Interview Response

**Question:** "What gets logged?"
```jsx
const [count, setCount] = useState(0);
const handleClick = () => {
  setCount(count + 1);
  setCount(count + 1);
  console.log(count);
};
```

**Good Answer:**
> "The console will log 0. Here's why: React batches state updates within event handlers, so both setCount calls queue updates but don't execute immediately. The console.log reads the stale `count` value from the current render. In the next render, count will be 1, not 2, because both updates captured the same initial value. This is a stale closure. To make it log 2 after the click, we'd use functional updates: `setCount(prev => prev + 1)` twice, since each updater receives the result of the previous one."

This shows: understanding of batching + closures + functional updates + ability to fix the issue.
